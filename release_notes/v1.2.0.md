# PrWaiter 1.2.0

**PR 状态变了会弹一条系统通知。**

自动刷新发现某个 PR 从一个状态变成另一个状态时通知你 —— 「#77400 等 review → 可合并」这种。
点通知直接跳到那个 PR。评审视角有新待办时也通知一条（「有人开始等我」）。

设置 → 刷新里可以关掉，旁边有「发一条试试」按钮，和跳转系统通知设置的链接。

## 几条刻意的取舍

**只有自动刷新发现的变化才通知。** 你自己点刷新时变化就在眼前，再弹一遍是噪音。

**刚启动的第一次拉取算基线**，不补报关机期间的变化 —— 一开机炸一屏比不通知更烦。
快照只放内存，不落盘。

**任何一头是「未知」都不报。** 拉取失败会把状态打成未知，一来一回就是两条假通知。

**一次多个变化汇总成一条**（列前 4 个），不刷屏。

## 顺带修的：本地构建拿不到通知权限

`build.sh` 原来完全不签名（ad-hoc）。而 **macOS 不给 ad-hoc 签名的 app 发通知权限** ——
签名每次构建都变，系统没法把授权记在一个稳定身份上。实测同一份代码、同样装在 `/Applications`：

```
ad-hoc 签名        ->  granted=false, UNErrorDomain error 1, alertStyle=0
PrWaiter Signing   ->  granted=true,  alertStyle=1（横幅）
```

失败时这个 app 连「系统设置 → 通知」列表都不会出现，看起来就像功能没做。

现在 `build.sh` 会读 `bootstrap_local_signing.sh` 写的 `signing.env` 并用那个稳定身份签包
（跟 `package_app.sh` 走同一条路），签不上就退回 ad-hoc 并说清楚原因。**Release 包一直是
CI 用稳定身份签的，所以装 DMG 的用户不受影响，通知可用。**

## 升级

设置 → 更新 → 「检查更新」→「下载并安装」。升上去后建议先点一次「发一条试试」确认能收到。
