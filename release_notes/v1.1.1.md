# PrWaiter 1.1.1

**修一个状态显示不准：「等维护者批准 workflow」被显示成「CI 运行中」。**

现在它是单独一档 —— **「CI 等批准」**（橙色，✋）。

## 为什么会错

fork PR 的 CI 要维护者点一下「批准运行」才会跑。这种状态下，GitHub 的 check suite 长这样：

```
status = COMPLETED        conclusion = ACTION_REQUIRED        0 条 check run
```

原来只读了 `status`，看到 `COMPLETED` 就当成「跑完了、什么都不会再来」。于是这个 PR 既没有
check 也没有必过项报上来，只好靠「必过项没报上来就算还在跑」那条规则兜成「CI 运行中」。

说法不准：**不点批准的话一步都不会跑 —— 它不是在跑，是在等人。**

现在连 `conclusion` 一起读，认出这一档。相应地把 `ACTION_REQUIRED` 从「失败」集合里挪了出来
——它不是失败。
