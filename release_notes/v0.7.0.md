# PrWaiter 0.7.0

**自动导入我的 open PR** —— 不用再手工填编号了。

## 之前的问题

添加 PR 得先去 GitHub 上找到编号，再回来一个个填进去。做 backport 的时候尤其烦：
一个改动分到 4.1 / 4.0 / 3.5 三个分支，就是三个新 PR、三次手工录入。而这些信息
GitHub 本来就知道。

## 现在

每次刷新会先查当前 gh 账号在该项目仓库下所有 open 的 PR，没见过的自动落到根级
最上面，然后照常拉状态。你只需要把它们拖进对应的描述块。

### 两条边界，都是刻意的

**每个 PR 只导入一次。** 删掉之后不会被导回来 —— 否则你清理掉的东西下次刷新
又冒出来，等于删不掉。

**已合并 / 已关闭的不会被自动清走。** 树上游那些已合并的 PR 正是判断下游有没有
解除阻塞的依据，自动清掉会让先后关系断掉。要清理还是用「清理已合并」。

不想要这个行为的话，设置的「刷新」一节里可以关掉，退回纯手工添加。

## 升级说明

老数据会自动迁移：树里已有但没记录过的 PR，首次刷新时会补记进 `imported`，
所以它们也不会被重复导入。

## 另外

修了签名脚本的三个隐患（只影响自己发版的人，不影响使用）：证书默认输出从 `dist/`
挪到 `~/Library/Application Support/PrWaiter/signing/ci/`（`dist/` 语义上随时可清空，
长期密钥搁那儿早晚被误删）、密码从只打印改成落盘、重跑不再静默覆盖已有证书。
