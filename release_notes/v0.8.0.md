# PrWaiter 0.8.0

**backport 自动聚合**，以及已关闭的关联 PR 也会进来。

## backport 直接挂到父 PR 下面

一个改动 backport 到多个分支，本来就是「等主干那个先合」的先后关系 —— 这正是
PrWaiter 的树想表达的东西，不该还要你手工拖一遍。

PR 标题里的 `(backport #77408)` 就是明确信号，认出来直接挂上去。也认
`backport of #N` 和 `cherry-pick #N`。实测 51 个 PR 里 40 个能解析出父 PR，
剩下 11 个正是主干 PR 本身。

认不出父 PR、或父 PR 不在树里的，照旧落在根级，手工拖。

## 已关闭的关联 PR 也会进来

机器人自动建的 backport 有时会失败被关掉。以前只导入 open 的，这类根本看不见 ——
你以为 backport 还在跑，其实早就死了。

但也不能把历史上几十个 PR 全倒进来。所以规则是：**已关闭 / 已合并的只收和已跟踪
PR 有关系的** —— 是某个已跟踪 PR 的 backport，或是某个已跟踪 backport 的父 PR。

效果是这样：

    修复 CVE                          7 个 PR  ✔5  ⊗2
      #76270                          已合并
        #76375  (backport #76270)     已合并
        #76376  (backport #76270)     已关闭   ← @mergify 建的，失败了
        #76377  (backport #76270)     已关闭   ← 同上
        ...

哪些 backport 成了、哪些死了，一眼看完。
